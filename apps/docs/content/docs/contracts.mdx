cdr-kit ships a standard library of CDR condition contracts plus a one-tx vault factory. Conditions are pure
`view` functions; all payment/state lives in separate mutating functions (the 2-step pattern).

## The interface

Every condition implements the verified 4-param, uuid-first shape:

```solidity
function checkReadCondition(uint32 uuid, bytes accessAuxData, bytes conditionData, address caller)
  external view returns (bool);
```

A `view` returns `false` (never reverts) on an unconfigured uuid. Configuration is **factory-only + atomic**:
`CdrKitVault.createVault` allocates the vault and configures the condition in one tx, closing the
front-running window — there is no permissionless `register()`.

## MVP conditions

| Condition | Gate |
|---|---|
| **SubscriptionCondition** | `paidUntil[uuid][caller] > now` — recurring access, two payment modes (native IP / WIP-royalty) |
| **TierGateCondition** | holds a Story PIL license of an allowed tier for the vault's IP (the IP-coupling moat) |
| **ComposableCondition** | AND/OR over child conditions, depth-capped, fail-safe `try/catch` |
| **CreatorWriteCondition** | fixed creator-only write gate (writes are not pluggable in MVP) |

## Typed bindings

`@cdr-kit/contracts` is the single source of truth for addresses + wagmi-generated ABIs:

```ts
import { aeneid, cdrKitVaultAbi, CDR_GAS_LIMIT } from "@cdr-kit/contracts";
// never hardcode an address elsewhere
```

<Callout type="warn" title="Set an explicit gas limit">
CDR precompile txs (allocate/write/read) run out of gas under `eth_estimateGas`. Use `CDR_GAS_LIMIT`
(2,000,000) on raw cast/forge calls; the SDK's `createVault` sets `gas: 3,000,000` for you.
</Callout>
