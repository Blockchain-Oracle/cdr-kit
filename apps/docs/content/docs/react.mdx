`@cdr-kit/react` is the headless React layer. It's `"use client"`, peer-deps `react`/`wagmi`/`viem`/
`@tanstack/react-query` (never bundles them), and themeable via `--cdr-*` CSS variables.

## Providers

```tsx
import { CdrProvider, CdrConfigProvider } from "@cdr-kit/react";

// Batteries-included: wires WagmiProvider + QueryClient + CDR context.
<CdrProvider apiUrl={apiUrl}>{children}</CdrProvider>;

// Already have your own wagmi stack (e.g. Privy)? Compose just the CDR context:
<CdrConfigProvider apiUrl={apiUrl}>{children}</CdrConfigProvider>;
```

## Components

```tsx
import { VaultGate, Vault, CdrSkeleton } from "@cdr-kit/react";

// Render-prop gate
<VaultGate uuid={id} auto loading={<CdrSkeleton />} fallback={<Subscribe />}>
  {(data) => <Chart bytes={data} />}
</VaultGate>;

// Or the Clerk-style compound
<Vault uuid={id}>
  <Vault.Loading>{(p) => <p>{p?.collected}/{p?.threshold} partials…</p>}</Vault.Loading>
  <Vault.Unlocked>{(data) => <Chart bytes={data} />}</Vault.Unlocked>
  <Vault.Locked><Subscribe /></Vault.Locked>
</Vault>;
```

## Hooks

| Hook | What |
|---|---|
| `useAccessVault(uuid)` | read + decrypt; exposes `{ status, data, error, progress, access }` |
| `useSubscribeAndAccess(uuid)` | the 2-step pay→read flow with status |
| `useCreateVault()` | create a vault via the factory |
| `useVault(uuid)` | vault metadata (tokenId, ipId, creator, termsId) |
| `useCreatorVaults(addr)` | a creator's vault token ids |
| `useDiscoverVaults()` | historical `VaultCreated` discovery (paginated getLogs) |
| `useVaultEvents()` | live `VaultCreated` feed (watch) |

The status union is first-class — `idle · connecting · paying · collecting-partials · ready · error · empty` —
so the multi-minute read is real UI state, with determinate progress, not a spinner.

## Theming & testing

```tsx
import "@cdr-kit/react/styles.css";

<CdrProvider appearance={{ variables: { "--cdr-skeleton": "#1b2030" } }} mockKit={createMockCdrKit()}>
  {/* mockKit runs every hook in-memory — no wallet/chain */}
</CdrProvider>;
```
